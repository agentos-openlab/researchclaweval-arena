# ResearchClawEval Arena 运行与评分规则

本文件规定公开任务的运行、评分和结果记录方式。每个任务的输入、输出、数据边界和计算预算以对应的 `contracts/` 文档为准；任务契约与本规则不一致时，按任务契约执行。

## §0 评测范围

当前版本提供五个任务：BabyLM-10M、MountainCar-Continuous、ARC-WBE-2026、PsyDefDetect 和 TDC-ADMET-Tox。仓库包含七个框架适配器。各框架支持的任务不同，当前状态以 `python3 scripts/arena.py list` 显示的结果为准。

比赛自测任务为 ARC-WBE-2026、PsyDefDetect 和 TDC-ADMET-Tox。正式比赛评测由主办方在其他任务上统一运行；自测成绩不计入最终排名。本仓库发布的历史榜单来自论文数据快照，不代表比赛正式成绩。

本规则规定公开 Arena 的本地运行、历史结果核验和榜单发布方式。榜单按任务分别排序，不合并跨任务总分，也不设总分冠军。新运行结果须经证据复核后才能发布。

## §1 榜单口径

公开榜单按**任务、模型和评测协议**分组。不同任务、模型或协议的记录分开排序，不将不同量纲的原始分合并为总分。

历史榜单复核已发布论文快照中的记录，不作为比赛正式排名。只有任务评分可复现、模型和协议明确、原生运行证据完整的记录才参与排序。未核验和缺失记录保留状态，但不显示名次。BabyLM 当前记录为框架自报困惑度，单独列出，不参与排序。

新运行默认保存在本地，不会自动发布到榜单。公开新结果前，须提供任务和数据版本、模型、协议、框架提交、原生执行记录、输出文件及评分结果，供维护者复核。不得将自报分标为已核验结果。

## §2 模型 API

需要模型 API 的框架从运行者本地环境读取 `OPENAI_BASE_URL`、`OPENAI_API_KEY` 和 `OPENAI_MODEL`。使用者自行选择与框架兼容的服务：

```dotenv
OPENAI_BASE_URL=https://your-provider.example/v1
OPENAI_API_KEY=在本机填写
OPENAI_MODEL=填写账户可用的模型名称
```

复制 `.env.example` 为 `.env` 后在本机填写。不得将密钥、含密钥的日志或本地 `.env` 提交到仓库。不同框架的模型兼容性可能不同；运行前应确认所选模型和接口满足该框架的要求。代码不得硬编码 API 密钥、模型名或用户专属地址。

运行器只将这三个 API 配置项传入框架容器，并在保存的标准输出中遮盖 API Key。自定义适配器也须遵守此要求。数据是否可联网，由任务契约分别规定。

## §3 数据

### 3.1 来源与许可

使用各数据集和上游框架时，须遵守其发布许可及用途限制。数据来源、版本和许可见任务契约与 `THIRD_PARTY_NOTICES.md`。本仓库不提交原始数据集。

### 3.2 下载与校验

使用 `scripts/setup_datasets.sh --dataset <topic-id>` 准备单项任务。脚本按公开来源和固定版本下载文件并校验已公布的 SHA-256。准备记录保存在本地数据目录。校验失败时停止运行，不得将旧文件作为新版本继续使用。

支持的任务 ID：`babylm`、`mountaincar_continuous`、`arc_wbe_2026`、`psydefdetect`、`tdc_admet_tox`。

### 3.3 固定数据切分

任务需要固定切分时，以仓库发布的清单和任务契约中的 SHA-256 为准。PsyDefDetect 使用对话级切分；评测记录的标签由运行器在挂载前移除。TDC 测试标签只供本地评分器读取。不得更换切分、从评测数据构造标签，或将评分数据复制到框架可见目录。

### 3.4 ARC 可见验证集

ARC-WBE-2026 的公开输入包含可见验证集和单独的评分集。框架可用可见验证集比较其方法，评分集真值不挂载到框架容器。运行器只挂载契约要求的公开目录；不得从其他本地路径加载数据。

## §4 适配器

每个适配器位于 `adapters/<id>/`，以 `adapter.json` 声明框架名称、固定上游提交、容器镜像、启动命令和支持任务。内置适配器可以通过 Dockerfile 从固定提交构建镜像。自定义适配器使用已有镜像。

自定义框架应提供含 `adapter.json` 的目录，并通过 `--adapter <目录>` 运行。清单中的启动命令须直接启动框架的原生研究流程；适配器可做环境转换和进程启动，不得自行生成框架结果或替框架输出原生标记。

适配器所需字段和示例见 [`templates/example-adapter/`](../templates/example-adapter/)。清单只应声明实际可启动的任务。`experimental` 表示尚未完成端到端公开验证，不表示该组合已能稳定复现结果。

## §5 运行记录与产物

### 5.1 启动命令

查看任务和框架：

```bash
python3 scripts/arena.py list
```

选择一个任务运行全部内置框架：

```bash
python3 scripts/arena.py run --topic psydefdetect --framework all
```

选择一个框架运行其已声明的任务：

```bash
python3 scripts/arena.py run --topic all --framework autoresearchclaw
```

一个任务和全部框架，或全部任务和一个框架是两种批次选择方式；不支持一次启动全部 35 种组合。标为 unsupported 的组合会出现在结果摘要中，批次以非零状态退出。`--dry-run` 可在下载数据或配置 API 前查看所选路由。

### 5.2 隔离与文件

每个组合使用新的工作目录。框架运行在 Docker 容器内；契约、任务输入、适配器和数据以只读方式挂载，只有当前工作区可写。任务契约规定的隔离方式优先，包括离线评分、隐藏标签分离和禁止外部下载。

批次目录中保存 `summary.json`、各组合的 `workspace/`、`input/` 和 `logs/e2e.log`。不要删除失败记录，也不要用失败尝试的旧产物覆盖新运行。API Key 不得出现在归档日志中。

### 5.3 任务输出

运行器检查各任务规定的文件和 trace 字段，再调用本地评分器。输出文件名、模式和评分顺序以各任务契约为准。分数缺失、产物不完整或校验失败时，结果记录为失败，不以占位值代替。

### 5.4 计算预算

任务预算彼此独立，见 `contracts/*_execution_budget.md` 及对应的 compute budget。运行器提供每容器超时限制；单个任务若规定更严格的限制，应遵守更严格者。失败后重试须保留原记录，并计入任务规定的预算。

### 5.5 原生执行标记

有效运行须包含适配器声明的原生标记。该标记必须由研究框架自身的执行流程输出，不得由 Dockerfile、壳层脚本或适配器代打印。运行器会同时检查标记、退出状态、所需产物和 trace。

### 5.6 样本标识

预测文件中的样本标识须来自任务输入。不得推断或重建标识，也不得更改任务要求的端点、类别或记录集合。各任务的检查方法见对应评分契约。

### 5.7 任务输入

运行器将任务契约和执行预算写入容器内只读的 `/input/prompt.txt`。框架应以该文件和任务数据作为输入，并记录输入版本。数据集中不应含有评分集标签或评分工具的私有信息。

### 5.8 实验计数

实验次数和策略线定义由单项任务契约规定，不设跨任务的统一次数。若任务要求多个实验，应在 trace 中记录配置、比较依据、失败情况和最终选择。重试或小幅调参是否计为新实验，按该任务契约处理。

## §6 评分与排名

### 6.1 本地评分

用户可重复运行框架和本地评分器。评分器只验证该任务规定的输出。BabyLM 的当前评分器读取框架报告的验证困惑度，因此标记为 `framework_self_reported` 且不具备入榜资格；这类数字不等同于独立复算结果。

### 6.2 单项排名

每项任务按其主要指标排序，指标方向见任务契约和 `results/leaderboard.md`。只有相同模型和相同评测协议下的结果才可比较。并列分数共享名次。次要指标不参与单项排序。

### 6.3 核验状态

榜单状态分为 `verified`、`self_reported`、`unverified` 和 `missing`。`verified` 结果须有可核对的评分值、评分数据指纹及原生运行证据；自报成绩标为 `self_reported`；缺少任一必要证据时标为 `unverified`；历史记录无对应结果时标为 `missing`。后两种状态不参与排名。

榜单按任务、模型和评测协议分别排序，不计算跨任务总分，也不设总分冠军。结果复核标准和生成命令见 [`results/README.md`](../results/README.md)。

## §7 贡献与结果提交

可通过 Pull Request 添加任务适配器、修正文档或提交经验证的运行结果。新结果须包含可公开复核所需的版本号、协议、评分产物和来源指纹。原始数据、API Key、用户专属地址和本地绝对路径不得提交。

对于已有框架，优先基于其公开上游版本适配；提交前检查许可证、模型配置读取方式、数据边界和任务输出。提交说明应指出完成过的验证和仍未覆盖的组合。

## 附录 A：扩展指标

`docs/metric-system.md` 描述实验轨迹和 LLM 评审的扩展指标。该指标体系是补充分析工具，不替代任务主要指标，也不参与当前历史榜的排序。若缺少所需证据，扩展指标应记为 `null`，不得从原始分数推算。
